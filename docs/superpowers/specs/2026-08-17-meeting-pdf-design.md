# 회의록 PDF 디자인 명세

작성일: 2026-08-17
상태: 목업 승인, 구현 전 검토

## 1. 목표

현재 `meeting.md`의 내용과 섹션 순서는 유지하면서, 회의록 PDF를 제공된 가이드북 레퍼런스의 시각 언어로 재구성한다. 결과물은 표지 한 쪽을 별도로 두지 않는 ‘회의록형 재해석’이다. 첫 페이지에서 제목, 회의 정보, 전체 요약을 바로 확인할 수 있어야 하며, 이후 페이지는 섹션 바·표·콜아웃·헤더·푸터를 일관되게 사용한다.

## 2. 범위

### 포함

- `output/meeting.pdf`의 A4 페이지 디자인과 자동 레이아웃
- 제목, 회의 개요, 전체 요약, 본문 섹션, 목록, 표, 콜아웃의 시각 계층
- 굵게, 기울임, 인라인 코드, 링크의 마크다운 렌더링
- 머리글, 바닥글, 현재 쪽/전체 쪽 표기
- 긴 내용의 자연스러운 페이지 흐름과 표 머리행 반복

### 제외

- `meeting.md`의 문장, 요약 내용, 사실관계 변경
- 별도 표지 페이지 추가
- DOCX를 PDF와 픽셀 단위로 동일하게 만드는 작업
- 회의록에 없는 정보를 추론하거나 새로 작성하는 작업

DOCX는 편집 가능한 기본 문서 역할을 유지한다. 이번 디자인 변경의 기준 산출물은 PDF다.

## 3. 레퍼런스 적용 원칙

- `report_master_prompt.md`의 A4 규격, 머리글·바닥글, 제목 계층, 표·콜아웃·코드 표현 원칙을 사용한다.
- `성장형_해커톤_마중물_연수_가이드북_6.html`의 넓은 여백, 네이비 중심 계층, 파란 섹션 바, 노란 강조 밴드, 연한 회색 카드, 절제된 선을 사용한다.
- 가이드북용 장식 요소는 줄이고, 회의 결과를 빠르게 찾는 데 필요한 요소만 남긴다.

## 4. 페이지 구조

### 공통 지면

- 용지: A4 세로, 210 × 297mm
- 본문 좌우 여백: 14mm
- 머리글 높이: 14mm
- 바닥글 높이: 11mm
- 본문 글자: 9.5~10pt, 줄간격 1.55~1.62
- 긴 단어와 한국어 문장은 글자 단위로 잘리지 않도록 처리한다.

### 첫 페이지

1. 머리글: 회의명·`회의록`, 오른쪽에 `01 / 전체 쪽수`
2. 영문 키커: `PROJECT MEETING RECORD`
3. 회의 제목: 25~30pt 굵은 글꼴, 핵심 한 줄에 노란 강조 밴드
4. 회의 정보 카드: `회의 개요`의 회의명·일시·장소·참석자를 2열 카드로 배치
5. 전체 요약 카드: `전체 요약`의 기존 문장을 연한 회색 카드 안에 배치
6. 남는 공간부터 다음 섹션을 자연스럽게 이어서 배치

필드 값이 비어 있거나 원문에 없으면 해당 값을 만들지 않는다. 빈 필드는 카드에서 제외하고 나머지 항목이 폭을 나누어 사용한다.

### 본문 페이지

- 머리글: 회의명·현재 주요 섹션, 오른쪽에 현재 쪽/전체 쪽
- `##` 제목: 자동 두 자리 번호와 파란 왼쪽 막대를 가진 연한 파란 섹션 바
- `###` 제목: 파란 마름모 표시와 얇은 하단선
- 본문: 회색 계열 글자, 문단 사이 3~4mm
- 바닥글: 프로젝트 표기와 생성 버전·날짜

## 5. 디자인 토큰

| 용도 | 값 |
|---|---|
| 네이비 | `#001035` |
| 보조 네이비 | `#12285A` |
| 파랑 | `#3F74C0` |
| 연한 파랑 | `#EAF1FA` |
| 본문 | `#3A3A3E` |
| 보조 글자 | `#6B6B70` |
| 선 | `#DCDCE0` |
| 카드 배경 | `#FAFAFB` |
| 강조 밴드 | `#FFE7A3` |

글꼴은 프로젝트에 포함된 Paperlogy Regular와 SemiBold/ExtraBold를 사용한다. 새 외부 글꼴이나 네트워크 의존성을 추가하지 않는다.

## 6. 마크다운 대응

| 마크다운 구조 | PDF 표현 |
|---|---|
| `# 제목` | 첫 페이지 대제목 |
| `## 섹션` | 번호가 붙은 파란 섹션 바 |
| `### 소제목` | 마름모 표시 소제목 |
| 일반 문단 | 본문 문단 |
| `- 항목` | 파란 마커 불릿 목록 |
| `1. 항목` | 굵은 번호 목록 |
| `**강조**` | 굵은 글꼴과 얇은 노란 강조 밴드 |
| `*기울임*` | 보조 강조 서식 |
| `` `코드` `` | 연한 회색 배경의 인라인 코드 |
| `[이름](URL)` | 파란 밑줄 링크와 클릭 대상 |
| 마크다운 표 | 네이비 머리행, 교차 행 배경, 반복 머리행 |
| `[추가 확인 필요: ...]` | 점선 테두리의 확인 예정 콜아웃 |

표나 목록 문법이 불완전하면 렌더링을 중단하지 않고 원문 문단으로 표시한다. HTML 특수문자는 먼저 이스케이프한 뒤 허용된 서식만 변환한다.

## 7. 구성 요소와 코드 경계

현재 `workers/render_report.py`는 편집 후 200줄 경고 구간에 있으므로 PDF 디자인을 같은 파일에 계속 추가하지 않는다.

- `workers/render_report.py`: CLI 입력, 기존 파일 보관, DOCX 생성, PDF 렌더러 호출
- `workers/report_pdf.py`: PDF 전용 문서 템플릿, 페이지 머리글·바닥글, 섹션·목록·표·콜아웃 Flowable 생성
- `workers/report_theme.py`: 색상, 글꼴 이름, 크기, 여백, ReportLab 스타일 정의
- `workers/report_common.py`: 마크다운 블록 및 회의 개요 메타데이터 파싱

각 파일은 한 가지 책임을 가지며 순수 코드 250줄 이하를 유지한다.

## 8. 데이터 흐름

1. `meeting.md`를 UTF-8로 읽는다.
2. 제목과 계층별 블록을 파싱한다.
3. `회의 개요`의 `- 키: 값` 항목을 정보 카드 데이터로 변환한다.
4. `전체 요약`을 첫 페이지 요약 카드로 분리한다.
5. 나머지 블록을 원래 순서대로 섹션·문단·목록·표·콜아웃 Flowable로 변환한다.
6. 두 단계 PDF 캔버스를 사용해 전체 쪽수를 포함한 머리글·바닥글을 그린다.
7. 기존 `meeting.pdf`는 현재 보관 규칙에 따라 `archive/`로 이동한 뒤 새 PDF를 저장한다.

## 9. 오류 처리와 보존 규칙

- 회의 정보가 없거나 비어 있어도 PDF 생성을 계속한다.
- 원문에 없는 회의 정보는 채우지 않는다.
- 글꼴을 찾지 못하면 현재와 동일하게 명확한 오류로 중단한다.
- 기존 PDF/DOCX 보관 동작과 공유용 제목 PDF 생성 동작을 유지한다.
- 섹션 제목과 첫 본문은 가능한 한 같은 페이지에 두되, 고정 간격 강제 페이지 나눔은 사용하지 않는다.
- 긴 표는 행 단위로 다음 페이지에 흐르게 하고 머리행을 반복한다.

## 10. 검증 계획

### 자동 테스트

- 회의 개요 메타데이터 파싱
- 인라인 마크다운 기호 제거와 링크·굵은 글꼴 적용
- 표 파싱과 반복 머리행 생성
- PDF A4 크기와 전체 쪽수 표기
- 빈 메타데이터, 긴 문단, 긴 표의 렌더링 성공
- 전체 Node 테스트 회귀 통과

### 실제 사용 검증

1. 설치된 `meeting-harness render output/meeting.md` 명령으로 실제 PDF를 만든다.
2. PDF 모든 페이지를 PNG로 렌더링한다.
3. 제목·표·콜아웃·머리글·바닥글의 겹침, 잘림, 과도한 빈 공간을 확인한다.
4. PDF 추출 텍스트에서 마크다운 기호가 남지 않았는지 확인한다.
5. `meeting-harness verify . --strict`를 통과시킨다.

## 11. 완료 조건

- 첫 페이지에서 회의명, 회의 정보, 전체 요약을 즉시 확인할 수 있다.
- 본문 섹션을 번호와 색상으로 빠르게 탐색할 수 있다.
- `**`, 백틱, 링크 문법, 표 구분자가 PDF에 문자 그대로 남지 않는다.
- 모든 페이지가 A4이고 머리글·바닥글·쪽수가 일관된다.
- 기존 회의록 내용과 섹션 순서가 유지된다.
- 자동 테스트와 실제 PDF 시각 검증이 모두 통과한다.
